TWO ACTIVE PLANNERS

Inside each planner

These methods run the actual Python planning engine. Changing a method applies to a new run.

Shared dynamics & execution

All methods use a sampled lane-level graph, lane-ending corridor groups and longitudinal SLSQP smoothing. SUMO executes the first-step targets with its independent safety controls.

Current path objective

The selected candidate minimizes path cost − 0.05 × margin proxy. The margin is the minimum count of distinct longitudinal positions per layer, not clearance in metres.

PAPER RELEVANCE

Aligned structure, simplified implementation

Implemented

RDF/SPARQL, four restriction types, reachable-state adjustment, dynamic programming, SQP smoothing and braking fallback.

Adapted

Discrete lanes replace 2D lateral dynamics. The graph is regenerated online; corridor grouping and costs differ from the paper.

Still missing

Geometric offline transition reuse, area-based connected corridors, GeoSPARQL reasoning, Frenetix and NGSIM-based validation.

Paper: Chen et al., IEEE Internet of Things Journal, 2025, DOI 10.1109/JIOT.2025.3613790. Detailed code mapping and enhancement priorities are saved in docs/PAPER_ALIGNMENT_REVIEW.md.

MEASURED RESULTS ONLY

Compare planners under the same conditions

Matches scenario, seed, duration, traffic density, communications, configuration, source hashes, SUMO version and network inputs. Uses the newest completed run for each planner.

A single matched seed is descriptive. Use repeated seeds and confidence intervals before drawing conclusions. Arrival and duration-limit outcomes must be interpreted separately; SUMO safety is enabled for every method.
