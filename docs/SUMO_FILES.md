# SUMO environment

| File | Role |
|---|---|
| sumo/network/nodes.nod.xml | Straight-road endpoints and the central signal junction, with a crossing road |
| sumo/network/edges.edg.xml | Three main-road lanes, crossing-road edges, road speeds and connectivity |
| sumo/network/road.net.xml | netconvert output: lane geometry, junctions, internal connections and generated traffic-light phases |
| sumo/routes/traffic.rou.xml | Car dynamics, ego and lead vehicle, main/crossing routes and surrounding traffic flows |
| sumo/additional/zones.add.xml | Visible planning-zone polygons; these are not physical collision obstacles |
| sumo/configs/demo.sumocfg | Links network, routes and additional files, simulation time step and report settings |

`main.py setup` invokes netconvert and checks its exit status. The central traffic light program is generated by SUMO in road.net.xml; its phases can be inspected in the `tlLogic` element. This project reads actual signal state using getNextTLS rather than assuming a fixed green/red schedule. The road geometry stays simple to make local planning decisions visible.

TraCI verification in tests retrieves ego speed, x/y, lane, heading, acceleration, next signal and surrounding vehicle states. The ego must move forward and a real signal must be observed. The integration test then builds RDF, runs SPARQL, plans and sends vehicle commands. The separate GUI smoke run also verifies the SUMO GUI binary and TraCI connection.

Controlled events: temporary lane-1 restriction at 10 s, surrounding vehicle merges into ego lane and brakes at 12 s, held at zero speed from 16–22 s, upcoming speed-cap update at 18 s in the demo, and all-lane emergency blockage from 8–18 s in the emergency scenario. Static, semi-dynamic and dynamic labels describe knowledge changes; all scenarios still include moving background traffic and a signal.

SUMO safety mode 31 and lane-change mode 512 constrain ego execution. Planned x/y do not directly teleport the vehicle. Actual observations and comfort metrics come from executed SUMO states. This adapter follows the first speed/lane target from each receding-horizon plan rather than an exact continuous steering trajectory.
